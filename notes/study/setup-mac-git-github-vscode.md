## 前提知識・用語整理

この手順を進める前に、各ツールの役割と関係性を理解しておくことを推奨します。

### Gitとは

ファイルの変更履歴を管理するソフトウェアです。「いつ・何を・どう変えたか」を記録し続けます。  
インターネットは不要で、自分のMac（ローカル）の中だけで動作します。

### GitHubとは

Gitで管理しているファイルをインターネット上に保存・公開できるサービスです。  
Gitの「ローカルの記録」をクラウドに預ける場所です。  
GitとGitHubは名前が似ていますが**別物**で、GitHubはGitの仕組みを前提として作られたサービスです。

> **例え：** Gitが日記帳、GitHubがその日記帳を預ける金庫

### コミットとプッシュの違い

- **コミット：** 変更履歴をGitに記録する操作（ローカルのみ）
- **プッシュ：** その記録をGitHubリポジトリに送り込む操作（インターネット経由）

コミットだけではGitHubには反映されません。プッシュして初めてGitHubに反映されます。

### GitHub Codespacesとは（参考知識）

GitHubが提供するクラウド上の開発環境です。  
VS Codeの画面はMacに表示されますが、実際の処理はGitHubのサーバー上で動いています。  
MacにGitがインストールされていなくても、ソースコードやGitの管理をクラウド上で全て完結することが可能です。

**ローカル環境との比較：**

| | ローカル環境 | GitHub Codespaces |
|---|---|---|
| VS Code | Mac上で動作 | Mac上で動作（画面表示のみ） |
| Git・ファイル処理 | Mac上で動作 | GitHubサーバー上で動作 |
| インターネット切断時 | 編集作業は継続可能 | 操作不可 |
| プッシュの通信経路 | Mac → インターネット → GitHub | GitHubのクラウド内でのやり取り |

**処理の流れ：**

```
ローカルの場合：
Mac上のVS Code → Mac上のGit（コミット） → GitHubリポジトリ（プッシュ）

Codespacesの場合：
Mac上のVS Code → Codespace上のGit（コミット） → GitHubリポジトリ（プッシュ）
```

**Codespacesが有効なケース（無料枠内）：**

- MacのローカルPC環境を汚さずに試したい実験的な作業
- 外出先でiPadなどGitが入っていない端末から開発したいとき
- チーム開発で環境差異をなくしたいとき

> **学習目的の場合：** Gitの仕組みを体で覚えるためには、ローカルにGitを入れる方法が最適です。  
> Codespacesはその学習過程をスキップしてしまうため、最初はローカル環境での構築を推奨します。

## 構築手順

### STEP 1：VS Codeのインストールと初期設定

VS Code（Visual Studio Code）はMicrosoft製の無料コードエディタです。  
テキスト編集からGitHub連携まで、この環境構築のすべての作業の起点になります。

#### 1-1. VS Codeのインストール

1. ブラウザで `https://code.visualstudio.com` を開く
2. `Download for Mac` をクリックしてダウンロードする
3. ダウンロードされたzipファイルを展開する
4. 展開された `Visual Studio Code.app` をアプリケーションフォルダに移動する
5. VS Codeを起動する

#### 1-2. 日本語化(任意)

VS Codeは初期状態で英語表示のため、日本語化拡張機能をインストールします。

1. VS Codeを起動する
2. 左サイドバーの拡張機能アイコン（四角いマーク）をクリックする
3. 検索窓に `Japanese` と入力し検索
4. `Japanese Language Pack for Visual Studio Code`を選び、インストールをクリックする
5. VS Codeを再起動すると日本語表示になる

---

### STEP 2：GitHubアカウントの作成と初期設定

#### 2-1. GitHubアカウントの作成

1. ブラウザで `https://github.com` を開く
2. `Sign up` をクリックする
3. メールアドレス・パスワード・ユーザー名を入力する
4. 案内に従って認証を完了させる
5. 登録したメールアドレスに確認メールが届くので、メール内のリンクをクリックして認証を完了させる

> **ユーザー名について：** GitHubのユーザー名はコミット履歴や公開リポジトリにも表示されます。  
> 後から変更することは可能ですが、他のサービスとの連携に影響する場合があるため、最初から慎重に決めることを推奨します。

#### 2-2. メールアドレスの非公開設定とダミーメールアドレスの取得

GitHubのコミット履歴にはメールアドレスが記録されます。  
実際のメールアドレスをそのまま使うと公開されてしまうため、GitHubが発行するダミーメールアドレスを使うことをお勧めします。  
このダミーメールアドレスをGitの設定に使うことで、実際のメールアドレスを公開せずにコミット履歴を自分のGitHubアカウントに正しく紐づけることができます。

1. GitHubにサインインした状態で右上のアイコンをクリックする
2. `Settings` をクリックする
3. 左メニューの `Emails` をクリックする
4. `Keep my email address private` にチェックを入れる
5. `123456789+ユーザー名@users.noreply.github.com` という形式のダミーメールアドレスが表示されるので控えておく

> **補足：** Gitに設定したメールアドレスがGitHubに登録しているものと一致していると、コミット履歴に自分のアカウントアイコンが表示され、  
> コントリビューショングラフ（プロフィール画面の草）にもカウントされます。  
> ダミーメールアドレスはこの紐づけを維持しつつ、実際のメールアドレスを隠すための仕組みです。

### STEP 3：Gitのインストールと設定

> ⚠️ おじさんメモ：GitをMacbookに入れるかどうか  
例えば、今後ラズパイなどを利用してそこを開発のベースとする場合は、MacbookにGitをインストールする必要はない。もちろん、MacにもラズパイにもGitを入れて、構築メモや技術情報はMacbookのGitで管理し、一方、pythonなどのソースはラズパイのGitで管理しラズパイ上で実行させる、ということもできる。

#### 3-1. コマンドラインデベロッパーツールのインストール

Appleが公式に提供している開発系ツール群です。Gitを使うために必要な基盤となります。  
Macの通常の使い方（ブラウザ・メール・写真など）には一切影響しません。  
このツールはMac本体にインストールされるため、複数のローカルアカウントがある場合でも一度のインストールで全アカウントから利用できます。

1. ターミナルを開く
2. 以下を実行する

```bash
git --version
```

3. 「コマンドラインデベロッパーツールをインストールしますか？」というダイアログが表示されたら `インストール` をクリックする
4. 数分待つ
5. インストール完了後、再度以下を実行してバージョンが表示されれば成功
6. アップデートがあるかもしれないのて、Macの「設定」-「一般」を確認しアップデートする（何度も表示される事象がありそう）

```bash
git --version
```

表示例：`git version 2.50.1 (Apple Git-155)`

#### 3-2. Gitのユーザー情報を設定する

コミット履歴に記録される作者情報を設定します。  
この設定はMacのローカルアカウントごとに独立しており、他のアカウントには影響しません。

```bash
git config --global user.name "GitHubのユーザー名"
git config --global user.email "STEP2-2で控えたダミーメールアドレス"
```

設定内容を確認する場合は以下を実行します。

```bash
git config --global --list
```

> **補足：** `user.name` はコミット履歴に表示されるテキストです。GitHubの認証とは無関係なため、  
> 厳密にGitHubのプロファイル名と一致していなくても動作しますが、合わせておくと管理しやすいです。  
> `user.email` はGitHubとのアカウント紐づけに影響するため、ダミーメールアドレスを正確に設定してください。


#### 3-3. Gitの動作について

> ⚠️ おじさんメモ：  
Gitがどのディレクトリをどのように管掌するか、気になったので色々と調べました。以下の記事にまとめています。

- [Gitの.gitディレクトリについて気になったこと](./git/git-dot-git-behavior.md)


#### 3-4. (補足) git config --global 設定項目一覧


| 設定項目 | 内容 |
|---|---|
| `user.name` | コミット履歴に記録される作者名。未設定の場合はコミット時にエラーになる |
| `user.email` | コミット履歴に記録されるメールアドレス。未設定の場合はコミット時にエラーになる |
| `init.defaultBranch` | git initしたときに最初に作られるブランチ名。デフォルトは`master`、GitHubに合わせて`main`にすることが多い |
| `core.editor` | git commitでメッセージを書く際に起動するエディタ。デフォルトは`vim` |
| `core.autocrlf` | 改行コードの自動変換。デフォルトは`false`。Macでは`input`にするとWindowsの改行コードをLFに変換して保存する |
| `color.ui` | ターミナルのgit出力を色付きにする。デフォルトは`auto` |
| `push.default` | git pushしたときにどのブランチにプッシュするかの挙動。デフォルトは`simple` |
| `pull.rebase` | git pullしたときにマージではなくrebaseを使うかどうか。デフォルトは`false`（マージ） |
| `core.ignorecase` | ファイル名の大文字・小文字を区別するかどうか。Macのデフォルトは`true`（区別しない） |
| `diff.tool` | 差分を表示する際に使うツール。デフォルトはターミナル表示 |
| `merge.tool` | マージの競合解決に使うツール。デフォルトはターミナル表示 |
| `credential.helper` | GitHubへの認証情報をどこに保存するか。Macのデフォルトは`osxkeychain` |
| `alias.*` | よく使うgitコマンドに短縮名をつける。例：`alias.st status` |

### STEP 4：SSHキーの設定

ローカルのGitからGitHubにプッシュする際の認証設定です。  
SSHキーを使うことで、毎回パスワードを入力することなく安全に通信できます。  
一度設定すれば以降は自動で認証されます。

#### 4-1. SSHキーの生成

ターミナルで以下を実行します。

```bash
ssh-keygen -t ed25519 -C "STEP2-2で控えたダミーメールアドレス"
```

- -Cはコメントを付加するオプション、複数の鍵を管理する際に識別しやすくするための目印
- 保存場所を聞かれたらそのままEnterを押す（デフォルト：`~/.ssh/id_ed25519`）
- パスフレーズを聞かれたら任意で設定する（空のままEnterでも可）

#### 4-2. 公開鍵の内容を確認する

```bash
cat ~/.ssh/id_ed25519.pub
```

`ssh-ed25519 AAAA...` で始まる1行のテキストが表示されます。これをすべてコピーします。

#### 4-3. GitHubに公開鍵を登録する

1. ブラウザでGitHubにサインインする
2. 右上のアイコン → `Settings` をクリックする
3. 左メニューの `SSH and GPG keys` をクリックする
4. `New SSH key` をクリックする
5. `Title` に任意の名前（例：`MacBook Air`）を入力する
6. `Key` に 4-2 でコピーした内容を貼り付ける
7. `Add SSH key` をクリックする

#### 4-4. 接続確認

```bash
ssh -T git@github.com
```

`Hi ユーザー名! You've successfully authenticated` と表示されれば成功です。

### STEP 5：GitHubリポジトリの作成

技術メモや構築手順書を保管するリポジトリを作成します。

#### リポジトリ名の指針

わかりやすい名前であれば何でも構いません。よく使われる例を以下に示します。

- `til`（Today I Learnedの略）
- `tech-memo`
- `setup-notes`

#### 公開設定の指針

- `Private`（非公開）：個人メモとして使う場合はこちらを推奨。後から公開に変更することも可能。
- `Public`（公開）：他の人にも参照してもらいたい場合。

#### フォルダ構成の推奨例

テーマごとにフォルダを分けておくと後から探しやすくなります。

```
tech-memo/
  README.md          ← このリポジトリの説明
  git/
    git-github-setup.md
  nodejs/
    nodejs-install.md
  docker/
    initial-setup.md
```

#### 作成手順

1. ブラウザでGitHubにサインインする
2. 右上の `+` → `New repository` をクリックする
3. リポジトリ名を入力する
4. 公開設定を選択する
5. `Add a README file` にチェックを入れる
6. `Create repository` をクリックする

---

### STEP 6：VS CodeとGitHubの連携(リポジトリのクローン)

クローンとは、GitHub上にあるリポジトリをMacのローカル（自分のパソコンの中）にコピーしてくることです。
初回クローン時にVS CodeとGitHubのOAuth認証が自動的に行われます。

1. VS Codeのエクスプローラーから「リポジトリの複製」をクリックする
2. 入力欄の下に表示される「GitHubから複製」を選択する
3. 「拡張機能GitHubがGitHubを使用してサインインしようとしています」というダイアログが表示されるので「許可」をクリックする
4. ブラウザが開いてGitHubの認証画面が表示されるので「Authorize Visual-Studio-Code」をクリックする
5. VS Codeに戻り、自分のGitHubリポジトリの一覧が表示されるので目的のリポジトリを選択する
6. 保存先フォルダのダイアログが表示されるので~/Projects/を指定する
7. クローンが完了するとVS CodeのエクスプローラーにリポジトリがGUIで表示される

## 日常的な作業の流れ
普段構築作業を行った際の手順書やメモをGitHubで保管するような場合、上記の環境構築完了後の通常作業はこの流れになります。

```
1. AIと対話して手順書をmdファイルで作成してもらう
2. mdファイルをダウンロードする
3. クローン済みフォルダ（リポジトリ内）にファイルを移動またはコピーする
4. VS Codeでファイルを開いて確認・編集する
5. 左サイドバーの「ソース管理」アイコンをクリックする
6. 変更内容にメッセージを入力する（例：「git環境構築手順書を追加」）
7. コミットしてからプッシュする
8. GitHubリポジトリに反映されたことをブラウザで確認する
```

## 補足・注意事項

### ローカルアカウントとGitの関係

- Gitプログラム本体はMac全体で共有されます（複数ローカルアカウントがあっても一度のインストールで足ります）
- `git config --global` の設定はMacのローカルアカウントごとに独立しています
- SSHキーの設定もMacのローカルアカウントごとに独立しています
- VS CodeのGitHubサインイン設定もMacのローカルアカウントごとに独立しています

### 複数端末での開発について

MacBookとiPadなど複数端末で同じリポジトリを使う場合の注意点です。

- 一方の端末で作業してプッシュしたら、もう一方の端末では作業前に必ずプルしてください
- プルとは、GitHubリポジトリの最新状態をローカルに取り込む操作です
- プルを忘れると、それぞれの端末で行った変更が競合する可能性があります

### コミットメッセージについて

コミットメッセージは後から見返したときに「何をしたか」がわかるよう、具体的に書くことを推奨します。

- 良い例：「Node.jsインストール手順書を追加」「git configのメールアドレスを修正」
- 避けるべき例：「更新」「修正」「test」
