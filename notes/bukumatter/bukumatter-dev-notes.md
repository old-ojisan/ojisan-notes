# ブクマッターの開発雑記

ブクマッターはユーザがシェアし合うオンラインブックマークです。  
https://bukumatter.com

登録したブックマークリストは、AIエージェントからJSONでアクセス・参照することができます。

## 📘　開発・リリースの背景

AIエージェントを利用する際に、ためになるURLの収集に手間取ったり、また折角収集したURLをmdファイルの中だけに留めるのがもったいないとの思いから、このサービスを開発・リリースしました。  

AIを活用したサービス・アプリを提供するより、AIを使う上で便利になるものを提供したいと思っています。

また、そもそもシステム開発に習熟していないので、改めて学習と実際の開発をしようと思い、それこそAIの力を借りながら進めたものです。2026年3月から学習を開始し、AIのサポートは大変役に立ちました。  

運営者は、IT業界に長らく身を置くものの、本格的な開発には携わってこなかった「おじさん」です。  
VS CodeやGitの使い方から始めて、ある程度理解が深まったと実感しますが、まだまだ研鑽が必要です。

## 📘　サービスの特徴

### 1. 気軽にマイページ登録できる

- 個人情報を取り扱うのは気が重いため、登録時に**メールアドレスなどは使用しません**。  
- また、登録時のアカウント名重複などの面倒も避けるため、アカウントは勝手に発行しています。

### 2. 他の人のブックマークを取り込める

- 自分でURLを登録するだけでなく、ブクマッターで公開される他の人のフォルダを取り込んで自分仕立てにすることができます。

### 3. ブックマークのフォルダごとにJSONのURL

- 登録したURLはフォルダごとに分けることができます。  
- フォルダ単位でURLのリストを返すJSONを公開できます。
  - AIエージェントにこのJSONへアクセスさせると便利。
- AIエージェントに毎回アクセスさせるのが嫌なら、JSONを保存してもらっても構いません。

### 4. フォルダ単位で公開 / 非公開の設定

- 作成したフォルダは公開するしないを設定できます。
- 自分個人だけのURLの管理は非公開フォルダを活用してください。
- サービスの主旨により、非公開のフォルダはJSONで参照できません。

### 5. インポート・エクスポートが可能

- ブックマークファイルのインポートも可能です。
- Chrome、Safari、Edgeのブックマークは概ね確認済みです。
- ただし、想定外のファイルがあるかもしれませんので、確約はできません。  

## 📘　想定利用シーン

運営者が個人的に欲しいと思った使い方もあります。

### 1. AIエージェントに読ませるオンラインのJSONとして

- AIに読み込ませるURL探すのも手間がかかります
- ブクマッターの利用者が共同してより良いURLリストを交換
- ブクマッターで公開するAIエージェントがJSONにアクセス

### 2. ディレクトリとして

- かつてのYahoo!のディレクトリのような使い方
- 検索だけでは知ることのできないサイト探索に
- 公式ホームページやSNSなど、様々な趣味のURLを取りまとめて発信してください
  - スポーツチームの公式ホームページや選手のSNS
  - アイドルのメンバーのSNS
  - 各種団体の公式ホームページ集、などなど

### 3. たまに見るYouTubeやSNS

- チャンネル登録するほどではないが、年に数回見るYouTube
- フォローするほどではないSNSアカウント
- そういう「たまに見る程度」置き場・逃がし場として

### 4. いろんなんブラウザから使う共通のブックマーク

- オンラインブックマークのど定番の使い方
- Chrome、Safari、Edgeなど複数のブラウザをまたぐブックマークとして

### 5. 秘密のブックマーク

- 前の4の用途でも、わざわざ公開する必要のないフォルダは非公開に
- 利用しているWebサービスのホームページなど

## 📘　現時点でできないこと

### アカウントの編集

現時点で、パスワード変更、アカウント名変更、アカウント削除の機能は提供できていません。

### サポート

マイページのURL(アカウント)を忘れた、パスワードを忘れた、そいうったお問い合わせを始め、サポート対応はできません。

### 非公開フォルダへのJSONアクセス

利用者間の情報交換につながらないため非公開フォルダのご利用は最小限に留めておきたい思いがあります。また、認証も絡むため今後も提供予定はありません。

### ニックネームやプロフィール

無機質な英数8文字のアカウント名しかありません。  
既存のSNSがありますし、現時点では検討していません。

## 📘　開発・運営におけるポイント

### コンシューマー向けサービス・UGC

B2BもB2Cにも携わってきましたが、特にB2Cの場合は、1%の不正な利用が残りの99%の通常の利用者の便益を圧迫する、とも言われていました。  

ブクマッターは利用者がサイトを登録するUGC（User Generated Content）のサービスです。従来であれば、システム化や人員体制によってチェックしていたところ、生成AIによって効果的に省力化できるようになったこともあり、本サービスの開発と公開に踏み切れた、というのはあります。

### クラウド

残念ながらこれまで私はクラウドに触れる機会がありませんでした。  
クラウドの存在も大きなポイントでした。

- 個人でも簡単に得られる可用性
- クラウドシステム自体がIaCを想定しているため、AIエージェントとの親和性が高い

現在は、Azureクラウドを利用しており、コストを抑えた構成で提供しています。  
利用者が増えて負荷が増すような嬉しい悲鳴になったら、やれる範囲で増強したいと思います。

### サービスサイド

- AzureクラウドのSWAとFucntions、Cosmos DBを利用

### 運営サイド

- 最低限の管理機能を開発し、管理画面として稼働
- 残りはClaude Code / Claude Coworkを活用し、運営ジョブを組み上げ
  - 特に、よくないURLの登録・公開は早めに検知したい
  - Azure AI Content SafetyはURLの文字列だけで判断するが、生成AIはより深く判断

## 📘　ハマった点など(備忘録)

- カスタムドメイン
  - Apexドメインの設定がレジストラのDNSで出来なかった
- bukumatterが「ブクマッター」でなく「ブクマター」なのは重々承知
- Azureトラブル
  - とある時期、異常に重くなるも自分の実装を疑った
  - Azureのサイト認証も異常に重い時がある
- Azure SWAでadminは予約語？
- ブックマークインポート
  - 各ブラウザで微妙にフォーマット差異がある
- 当初はGitブランチに不慣れ
- GitHub-Azureのデプロイ環境整備(dev/prod)
  - SWA作成時にGitHubを連携させると、SWAがリポジトリにymlを書き込んでくれる
  - PR open/close時のデプロイ方針
  - devから作業ブランチを切って修正後にPRすると、devにステージングデプロイ
- favicon
  - 利用者が登録するURLのfaviconをどうするか問題
  - 本サービス自体のfavicon作成も当初うまく出来ず
- Xへのシェア(OGP)の実装工夫
  - Xシェア時に、Xが読み込む情報取得はJavaScriptなど動的処理が動かない
  - 各フォルダのXシェアでは、事前のHTML組み上げにより対応
- デザイン
  - AIに「Webサイトの基本的なデザインのサンプルを複数用意して」といってベタ打ちHTMLを複数用意してもらった
